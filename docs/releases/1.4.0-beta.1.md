# Smart Resource Multiplier 1.4.0-beta.1 for Minecraft 26.3

This is a compatibility port of the Minecraft 26.2 dual-loader 1.3.0 source. It is a beta source update, not a storefront release; `release_ready=false`. Install exactly one loader-specific JAR and Java 25.

## Preserved behavior and required adaptation

The only production Java edit changes FallingBlockEntityMixin's landing redirect from `Level.setBlock(..., flags)` to `Level.setBlockAndUpdate(...)`, matching Minecraft 26.3's actual landing call. It retains the original return value, only marks a successfully placed protected block, and clears carried protection after success. All other production Java files and resources retain the 1.3.0 implementation: rule precedence, 0x through 64x multipliers, block/entity/shearing scope, XP, legal stacks, output budgets, permissions, config schema 3, saved-data identifiers, payloads, and GUI behavior.

A new shared GameTest invokes real falling-entity ticks and verifies both placed/protected sand and natural sand. It verifies removal of the old marker, transfer on landing, and clearing of the carried flag. The pre-existing assertions remain intact, including Looting III's expected 21 nuggets after multiplication.

Development-only fixtures now use 26.3 loot `modifier`/`condition` fields and `type` discriminators, integer number providers, optional condition holders, narration triggers, damage cooldown, and explicit GameTest dimensions. NeoForge test servers explicitly use `white-list=false`, matching their existing offline local-test setup; this does not alter players' server settings.

Use JDK 25 and the repository Gradle wrapper. On Windows substitute `.\gradlew.bat` for `./gradlew`.

```sh
python tools/validate_package.py

python scripts/test_modmenu_integration.py
python scripts/test_structured_tooltip_composition.py

./gradlew -p neoforge --no-daemon runMigrationRestartServerTest runClientCategoryTest
```

The shell multiplayer runners use `xvfb-run` on Linux. The local Windows run invokes the same Gradle server/client tasks in separate JVMs and checks the runners' exact success markers, decoder rejection, clean exit codes, and timeouts. Test worlds and logs stay in ignored build directories.

## Compatibility limits

This port preserves the mod's behavior against the existing regression suite. It does not claim identical FPS across Minecraft releases or certification with every third-party mod. Existing loader-specific NeoForge deprecation warnings for vanilla Shearable and Honeycomb maps remain from the shared implementation; changing those compatibility boundaries is outside this behavior-preserving port. Runtime logs can contain host OSHI performance-counter warnings and offline-development authentication messages, which are separate from the mod's assertions.

The captured Fabric-to-NeoForge migration fixture remains the original authentic 26.2 chunk; the 26.3 run tests importing and persisting that fixture across two server JVMs. It is not a complete-world or modpack migration matrix. Keep the existing one-way loader migration guidance.

## Mouse-input correction during gameplay testing

Manual testing found that structured submenu rows ignored left clicks: the old literal button `0` no longer represents left click in 26.3. Both loaders now use `InputConstants.MOUSE_BUTTON_LEFT` (`1`). The previous GUI tests bypassed mouse dispatch by invoking row actions directly. Fabric GUI and NeoForge multiplayer tests now send mouse press/release events through the current screen, retaining the existing navigation and staged-setting assertions. The Fabric regression failed before the production fix while waiting for the clicked category editor.
